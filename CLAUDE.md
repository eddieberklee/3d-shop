# 3d-shop

- Check before you report done: `npm run check` (typecheck and production build).
- Renderer setup is in `src/stage.ts`. Scene content goes on `stage.scene`; call `stage.invalidate()` after each change, because frames are drawn on demand (the cloud drift in `src/hallway.ts` also redraws at 30 fps while the tab is visible).
- This repo is public. Do not commit `.env` files or secrets.
- Shop data comes from `src/shop.ts` (Shop MCP at `https://mcp.shop.com/`, no key). Fetch live data, keep every returned URL unchanged, and send the shopper to `continue_url` to pay. Checkouts are real: do not pay one in a test.
- Scene: `src/hallway.ts` builds the hall; `setStorefrontImage(shop, url)` puts an image on a shop front. `src/controls.ts` owns the camera (look limits, drag-the-lane-floor to walk, easing and momentum).
- Shops: `src/journey.ts` runs the tap, enter and exit animation; `src/shopRoom.ts` builds the one shared shop room. Control modes are `hall`, `shop` and `cinematic` (`src/controls.ts`).
- Dev-only URL parameters for visual checks: `?view=z,yaw,pitch`, `?shop=7&yaw=90`, `?door=7,0.6`, `?tap=x,y`.
- Shops and their shelf products are fixed in `src/shopList.ts` (same shops, same order, each visit). Do not replace it with a live search. At page load `src/shopOrder.ts` sorts `SHOPS` in place so the shops with the most generated models are nearest; always index `SHOPS` by hall index after that. Dev-server endpoints are Vite plugins in `server/`.
- Shelf order follows click counts. Fill a shop's shelf slots in `shelfOrder(shop)` order and call `recordProductClick(id)` when a product is tapped (`src/clicks.ts`). `server/productClicks.ts` keeps the counts in `.data/product-clicks.json` (git-ignored). Clicks change the order only, never which products a shop has. Each shop pins 10 products; the room shows as many as it has shelf slots, in `shelfOrder` order.
- Shelf cubes and try-on: `src/shelfCubes.ts` puts each pinned product's photo on the front of a placeholder cube (back wall); a tap opens `src/tryOn.ts` (camera selfie, spinner, result). `server/tryOn.ts` (`POST /api/try-on`) calls Gemini `gemini-3-pro-image`; it has no Worker route, so try-on is dev-server only.
- Secrets: `.env.local` (git-ignored) holds `GEMINI_API_KEY`. Read it only in `server/` or `scripts/`, never in `src/`, and never print it.
- Deploy: `npm run deploy` (Cloudflare Worker `3d-shop`, config `wrangler.jsonc`). Cloudflare serves `dist`; only `/api/*` runs `worker/index.ts`, which mirrors the `server/` endpoints (click counts in D1 database `3d-shop`, schema in `migrations/`). A new dev-server endpoint needs a Worker route too, or it is dev-only. Deploy from a clean worktree: Vite copies every file in `public/` into `dist`.
- 3D product models: `scripts/generate-models.mts` (green-screen image with `gemini-nano-banana-2.1`, then Gemini 4 Neon and Argon each write a list of solids that `scripts/modelSpec.mts` turns into a `.glb`). Output is `public/generated/models/` (git-ignored) with `manifest.json`, keyed by product id. Compare results at `/model-preview.html`.
